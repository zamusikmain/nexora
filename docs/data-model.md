# Data model
Таблицы: departments, users, auth_sessions, login_throttles, document_types, documents, document_versions, comments, audit_events. Alembic добавляет alembic_version.
CHECK: user role/status, document status, positive version/size. UNIQUE: user email, department/type code, document number, storage key, (document_id,version_number), (document_id,id). Foreign keys связывают пользователей, подразделения, типы, документы, версии, авторов и actor. documents(id,current_version_id) -> document_versions(document_id,id), nullable до первой версии.
Sequence document_number_seq глобальная, не сбрасывается ежегодно; формат DOC-<UTC year>-<at least six digits>; пропуски при rollback допустимы. Версии выделяются под FOR UPDATE document lock с max existing version + 1; UNIQUE — дополнительная защита. PostgreSQL triggers запрещают UPDATE/DELETE versions и audit.
Indexes: user department; session user/expiry; document owner/type/department+status; version/comment document; audit action/target/time. Search ILIKE title/number, без fulltext/trigram/vector индексов.
JSON business_metadata — расширяемые domain fields; document_types.metadata_schema — validated declarative field schema with generated UI.
0001_core — explicit frozen migration с tables/constraints/indexes/sequence/triggers и reverse downgrade; runtime models не импортируются.


Enterprise additions: folders/favorites, document folder/trash/revision and structured metadata (0002/0003); workflow_templates, workflow_instances, approvals, workflow_events (0004); immutable file_scans attestations (0005); public session UUID/user-agent (0006). Workflow templates/events are immutable, instance document/version/template/snapshot bindings are protected, one RUNNING instance per document is enforced by a partial unique index. Approval selectors and visibility indexes support assigned-user lookups. All migrations are additive and independent of runtime models. There is no tenant_id boundary yet.
# ACL Revision 2 candidate schema

Migration `0007_acl` adds six tables: `acl_authorities`, `acl_department_policies`, `access_grants`, `grant_endorsements`, `review_receipts`, `receipt_revocations`; nullable version metadata snapshots and comment version/process/stage provenance. It does not rewrite old documents, users, assignments, versions or events. Grant scope, endorsements and receipts are immutable. Downgrade blocks once new business records/snapshots/scoped comments exist. See [compatibility verification](acl-implementation.md) and [cutover/rollback](acl-cutover.md). This schema has only been applied in isolated environments.
