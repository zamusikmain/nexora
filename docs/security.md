# Security: implemented controls and remaining gaps

2026-10-08 update: ACL Revision 2 is implemented and verified in isolated tests in the working tree, **not deployed to the working database/containers**. See [ACL implementation](acl-implementation.md) and [safe cutover](acl-cutover.md). The older authorization description below records the 2026-10-07 deployed baseline; it does not describe the new candidate policy.

Current enterprise increment, 2026-10-07. Commercial security readiness is not established.

## Authentication and authorization
Local passwords use Argon2id. Random session cookies are HttpOnly, SameSite=Lax and Secure in production. Only a SHA-256 token hash is stored; mutations require exact Origin and session CSRF. ACTIVE status/role are reloaded on every request. Public session UUIDs are independent of cookie/token hashes. Users can list/revoke their own sessions; ADMIN can revoke a user's sessions. New logins retain at most 20 active sessions per account. Account and client-address throttles are transactionally locked (20 failures/15 minutes). The client address is the direct peer unless that peer matches `TRUSTED_PROXIES` (CIDR, IP or hostname; compose default `web`); only then is X-Forwarded-For read right-to-left, skipping trusted hops. IPv6 clients are bucketed per /64. When no untrusted client address is available, only the account bucket applies, so failures through the shared web proxy no longer lock out every user. Next.js passes a client-supplied X-Forwarded-For through unchanged: production's HTTPS reverse proxy must overwrite or append it and be listed in `TRUSTED_PROXIES`; without it the per-client bucket is spoofable (the account bucket still applies).

Owner/admin writes require editable document state. Owner, department manager, administrator and assigned workflow participant read policies apply to list/count/detail/child resources/download. Foreign documents/versions return 404. Template administration and user/audit administration are backend protected. Participants retain document read access after completion; future edits and all versions remain visible under that policy. Granular resource ACL/revocation, group/manager selection, delegation, MFA/TOTP, OIDC/Entra and organization isolation are not implemented. Confidentiality is classification metadata and does not grant or restrict access by itself.

## Private storage and antivirus
PDF/TXT/DOCX uploads are bounded to 20 MiB, validated by extension/MIME/content, written into private quarantine, scanned, then atomically promoted. Production only accepts ClamAV: unavailable, timed-out or unrecognized replies reject the upload. Development bypass is explicit and displayed in UI. No mock scanner exists in the production path. ClamAV uses the documented [INSTREAM protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). `compose.security.yaml` pins the official ClamAV image digest and retains signatures in a private volume.

Clean scan attestations bind immutable version IDs to their SHA-256 and cannot be updated/deleted. Old uploads are not automatically marked safe. Before switching to production run `python -m app.scan_existing` (sample only) then `--apply` with ClamAV configured; it checks exact legacy bytes, scans and audits. Blocked legacy versions remain preserved and are inaccessible through production download/submit/workflow start until a valid attestation exists. Attestations currently do not expire and are not periodically rescanned; engine/signature-version tracking and an asynchronous scanner worker remain future work. Synchronous scanning may hold a document lock up to the configured deadline.

Downloads validate size/SHA-256 before streaming and require production scan evidence. Original versions, workflow events and audit rows have immutable database triggers. Restoring a version creates a new file/version; trash is recoverable. No purge endpoint bypasses retention. Database owner access can bypass triggers; WORM/tamper-proof storage is not claimed. Antivirus cannot guarantee full PDF/DOCX safety or content disarm.

## Operations
`python -m app.cleanup` is a dry run; `--apply` only removes old unreferenced generated blobs/quarantine files, after a complete successful DB reference read and committed start audit. Minimum grace is 24h (default 48h); all immutable referenced versions, including trash, are retained. Failure to read references causes zero filesystem deletion. Operator scheduling, session/throttle cleanup and durable background jobs remain unimplemented. See [backup/restore](backup-restore.md) for actual recovery verification.

Production settings reject demo seed/password, development scanner bypass, non-HTTPS/invalid origin and the known local DB password. Runtime errors return safe codes/request IDs; request logs omit bodies, queries, identities and exception messages. Web sets CSP, frame denial, nosniff and referrer policy; CSP still needs unsafe-inline for current Next rendering and is not a strict nonce policy. TLS termination, secrets escrow, database least privilege, full security review and production deployment are pending.
