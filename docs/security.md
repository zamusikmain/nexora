# Security baseline and limitations
Каждый запрос проверяет серверную сессию, срок и ACTIVE status пользователя из БД. Random session token хранится в БД как SHA-256 hash; cookie HttpOnly/SameSite=Lax/Secure вне development. Срок 12 часов, logout удаляет запись. Роль/статус проверяются заново на следующих запросах. В браузере сохраняется только язык; CSRF token держится в памяти и возвращается /auth/me. Mutation требует точный Origin и session CSRF header (login — только Origin). CORS не включён.
Централизованный RBAC: owner — свои документы, MANAGER — своё подразделение, ADMIN — все. REVIEWER/APPROVER/LEGAL пока имеют owner-level access. Denied resource returns 404. Write требует owner/admin и editable state; child resource проверяется на принадлежность документу. Catalog names доступны authenticated users, users/audit только ADMIN.
Private volume, UUID keys, path containment, exclusive creation. Filename NFKC normalization, удаление path separators/control chars. PDF/DOCX/TXT extension и declared MIME allowlist плюс content checks. TXT: UTF-8 без NUL. PDF: signature. DOCX: обязательные ZIP entries, лимиты count/uncompressed size, запрет encrypted/macros/entities. Archives не извлекаются. 20 MiB file cap, body cap до multipart spooling, SHA-256. Attachment downloads + nosniff. UPDATE/DELETE triggers защищают versions/audit; composite current-version FK предотвращает чужой pointer.
Проверки не обнаруживают все malicious/polyglot files, нет antivirus/full parser/content disarm. Оригиналы остаются недоверенными.
Audit и действие в одной DB transaction, actor/action/target/time/request ID и safe metadata. Нет паролей/tokens/file contents/full comments в audit. Ошибки — machine codes и correlation ID. Logs — method/status/duration и exception class, без exception SQL payload. DB owner может обойти triggers; tamper-proof retention не заявляется.
Остаётся: TLS/secrets/database role separation, trusted proxy rate limiting, session cleanup, malware scanning, orphan reconciliation, backup/restore, optimistic conflicts, расширенный security/load/accessibility review. Будущий RAG обязан применять resource policy до retrieval.
